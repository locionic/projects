In the previous lesson, we uncovered a critical flaw common to all LLM applications: Large Language Models are frozen at their training cutoff date. When an agent is asked:
> *"What meetings do I have tomorrow?"*

The model cannot answer accurately because it has no intrinsic internal clock. It does not know whether "today" is a Tuesday in September or a Friday in April.

In this lesson, we eliminate this temporal blind spot by dynamically injecting live date and time context into the AI Agent node using n8n expressions.

## The Temporal Blind Spot Explained

```
Without Dynamic Time Injection:
User: "What meetings do I have tomorrow?"
LLM: (Inspects training cutoff: 2024? 2025?) -> Hallucinates random date or fails calendar filter!

With Dynamic System Prompt Injection:
System Prompt: "Current date and time: Wednesday, September 16, 2026 07:00 AM UTC."
User: "What meetings do I have tomorrow?"
LLM: "Tomorrow is Thursday, September 17, 2026. Querying calendar for 2026-09-17..."
```

## Step 1: Open the Planner AI Agent System Prompt

1. Double-click the `Planner AI Agent` node on your canvas.
2. In the options section, locate **System Message** (or click **Add Option** -> **System Message**).
3. The System Message field allows you to define foundational behavioral instructions that prepend every LLM invocation.

## Step 2: Inject Dynamic Luxon Expressions

n8n includes the powerful **Luxon** datetime library built directly into its expression engine. You access the current execution timestamp via `$now`.

In the **System Message** field, enter the following prompt template:

```text
You are an Executive Daily Planning Assistant.
Your core objective is to analyze the user's schedule, cross-reference environmental factors, and compile actionable daily briefings.

CURRENT REAL-WORLD TEMPORAL CONTEXT:
- Current Timestamp: {{ $now.toISO() }}
- Current Human Date: {{ $now.format('cccc, LLLL d, yyyy') }}
- Current Time: {{ $now.format('hh:mm a') }} (Timezone: {{ $now.zoneName }})

OPERATIONAL RULES:
1. Always calculate relative dates (e.g. "today", "tomorrow", "this afternoon", "next Monday") relative to the Current Timestamp above.
2. When querying calendar events for "tomorrow", calculate the start time as: {{ $today.plus({ days: 1 }).toISO() }} and end time as: {{ $today.plus({ days: 1, hours: 23, minutes: 59 }).toISO() }}.
3. Never guess dates. Use the exact timestamps provided in context.
```

<Callout type="info" title="Luxon Date Formatting Cheat Sheet">
- `{{ $now.toISO() }}`: `2026-09-16T07:00:00.000Z` (Standard ISO 8601 for API filters)
- `{{ $now.format('cccc, LLLL d, yyyy') }}`: `Wednesday, September 16, 2026`
- `{{ $now.format('yyyy-MM-dd') }}`: `2026-09-16`
- `{{ $today }}`: Midnight of the current day (`2026-09-16T00:00:00.000Z`)
- `{{ $today.plus({ days: 1 }) }}`: Midnight of tomorrow
</Callout>

## Step 3: Verifying Temporal Awareness in Chat

1. Click **Back to canvas** and open the chat widget.
2. Submit the query:
   > *"What is the current date and time?"*
3. The agent reads the injected system message and immediately replies with the exact, live date and time!
4. Now test relative calendar queries:
   > *"List all interviews scheduled for tomorrow."*
5. The agent accurately computes tomorrow's date, filters the calendar observations, and reports:
   > *"Tomorrow, September 17, 2026, you have one interview scheduled: Job Interview with Anthropic from 10:00 AM to 11:30 AM."*

The assistant is now fully anchored in real time.

<Exercise title="Construct a Timezone Conversion Expression">
Your n8n server runs in UTC (`Europe/London`), but your user is based in San Francisco (`America/Los_Angeles`).

How would you format the current time in the system prompt so the assistant knows the user's local Pacific time?

<SolutionToggle>
Using Luxon's `setZone` method:
`{{ $now.setZone('America/Los_Angeles').format('cccc, LLLL d, yyyy hh:mm a (z)') }}`

This converts the server's UTC timestamp into the user's local Pacific Time (e.g. `Tuesday, September 15, 2026 11:00 PM (PDT)`).
</SolutionToggle>
</Exercise>
