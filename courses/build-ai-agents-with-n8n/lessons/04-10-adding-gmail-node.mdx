Having an AI agent gather calendar events, weather forecasts, and web intelligence in a chat window is convenient, but the real power of an executive assistant is delivering a consolidated morning briefing to your inbox before you start your day.

In this lesson, we connect the **Gmail Tool** to our AI Agent.

```
                  [ Planner AI Agent ]
                    ├── Model: OpenAI Chat Model
                    ├── Memory: Window Buffer Memory
                    └── Tools (Orange Port)
                          ├── [ Google Calendar Tool ] (Agenda data)
                          ├── [ OpenWeatherMap Tool ]  (Forecast data)
                          ├── [ SerpAPI Search Tool ]  (Research headlines)
                          └── [ Gmail Tool ]           (Dispatches HTML Daily Briefing)
```

## Step 1: Attach the Gmail Tool Node

1. On your canvas, locate the `Planner AI Agent` node.
2. Click the **+** icon beneath the **Tools** port (orange port).
3. Search for **Gmail** and select the **Gmail** tool node.
4. Rename the node to:
   ```
   send_email_report
   ```

## Step 2: Configure Gmail OAuth2 Credentials

1. In the Gmail node configuration, select **Credential to connect with** -> **Create New Credential** -> **Gmail OAuth2 API**.
2. Sign in with your Google account.
3. Grant permission for n8n to compose and send emails on your behalf.
4. Click **Save**.

## Step 3: Configure Tool Parameters and Destination

Configure the node parameters:
- **Tool Description**: Leave set to **Set Automatically**. The description informs the agent that this tool sends an email message to a specified recipient with a subject line and body.
- **Resource**: `Message`
- **Operation**: `Send`
- **To**: Enter your personal email address (e.g. `yourname@gmail.com`).
- **Subject**: Enter a default subject pattern or let the LLM generate one:
  ```
  Daily Executive Intelligence Brief - {{ $now.format('yyyy-MM-dd') }}
  ```
- **Email Type**: Select **HTML** (ensures tables, bold text, and clickable URLs render cleanly).

## Step 4: System Prompt HTML Formatting Instructions

To ensure the agent formats the email body professionally rather than sending unformatted plain text, update the **System Message** in the `Planner AI Agent`:

```text
EMAIL FORMATTING SPECIFICATION:
When calling the send_email_report tool, the 'message' parameter MUST be formatted in valid HTML:
1. Use clean inline CSS styling with a sans-serif font (Arial, Helvetica, sans-serif).
2. Format the daily agenda as an HTML table with column headers: Time, Event Title, Location, Notes.
3. Include an Alert Box (light gray background, dark border) displaying the weather forecast.
4. Include a dedicated section with bullet points for company research headlines with clickable hyperlinks.
```

## Step 5: Testing End-to-End Email Dispatch

1. Open the chat widget.
2. Submit the command:
   > *"Compile my daily briefing for tomorrow and send it to my email."*
3. Watch the agent coordinate all four tools:
   - Queries `fetch_calendar_events` for tomorrow.
   - Queries `get_weather_forecast` for San Francisco.
   - Queries `serpapi_web_search` for Anthropic.
   - Formulates the comprehensive HTML email body.
   - Invokes `send_email_report`.
4. Open your email client: your executive briefing appears in your inbox formatted with styled tables, weather badges, and hyperlinked company research!

<Callout type="info" title="Dynamic Recipient Flexibility">
If you want the agent to be capable of emailing reports to colleagues or clients, leave the recipient parameter flexible. The agent can extract recipient email addresses directly from the conversation prompt.
</Callout>

<Exercise title="Prevent Accidental Mass Emailing">
Suppose the user says: *"Email everyone attending my afternoon meeting a reminder."*
If the agent has access to `send_email_report`, how should you constrain the agent to prevent emailing external attendees without confirmation?

<SolutionToggle>
Enforce a recipient security constraint in the System Prompt:
```text
RECIPIENT RESTRICTION:
The send_email_report tool is strictly restricted to sending emails to the primary user (yourname@gmail.com). You are explicitly forbidden from dispatching emails to meeting attendees or third-party addresses without explicit human approval.
```
</SolutionToggle>
</Exercise>
