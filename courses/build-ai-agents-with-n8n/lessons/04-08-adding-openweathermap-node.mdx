An executive assistant should not merely recite calendar titles; it should anticipate practical needs. If your calendar indicates an outdoor lunch meeting or a coffee meetup across town, your assistant should report whether you need an umbrella or a coat.

In this lesson, we connect the **OpenWeatherMap Tool** to our AI Agent.

```
                  [ Planner AI Agent ]
                    ├── Model: OpenAI Chat Model
                    ├── Memory: Window Buffer Memory
                    └── Tools (Orange Port)
                          ├── [ Google Calendar Tool ] (Discovers "Starbucks, San Francisco")
                          └── [ OpenWeatherMap Tool ]  (Queries "San Francisco" weather)
```

## Step 1: OpenWeatherMap Account and API Key

1. Navigate to [openweathermap.org/api](https://openweathermap.org/api).
2. Register for a free account.
3. Under your account name in the top right corner, select **My API Keys**.
4. Generate a new key named `n8n-agent-key` and copy the 32-character hexadecimal token.

<Callout type="warning" title="API Key Activation Delay">
New OpenWeatherMap API keys can take between 10 to 30 minutes to activate globally across their edge servers. If n8n returns `HTTP 401 Unauthorized` immediately after creation, wait a few minutes before re-testing.
</Callout>

## Step 2: Attach the OpenWeatherMap Tool Node

1. On your n8n canvas, locate the `Planner AI Agent` node.
2. Click the **+** icon beneath the **Tools** port (the orange port).
3. Search for **OpenWeatherMap** and select the **OpenWeatherMap** tool node.
4. Rename the node to:
   ```
   get_weather_forecast
   ```
5. Configure credentials:
   - Create a new credential under **OpenWeatherMap API**.
   - Paste your API key into the **API Key** field and click **Save**.

## Step 3: Configure Tool Parameters

- **Tool Description**: Leave set to **Set Automatically**. n8n supplies a detailed schema informing the LLM that this tool retrieves current weather conditions, temperatures, and forecasts for any named city or geographic coordinate.
- **Resource**: `Current Weather`
- **Format**: `Standard (Imperial or Metric)`
- **Language**: `English`

Click **Execute step** with a sample city (e.g. `San Francisco`) to verify API connectivity. OpenWeatherMap returns temperature, humidity, wind speed, and weather condition strings (e.g. `"Clear sky"`, `"Light rain"`).

## Step 4: Testing Multi-Tool Chaining

Now test the agent's ability to chain calendar observations into weather queries:

1. Open the interactive chat widget.
2. Ask:
   > *"What is the weather like for my meeting with Paul tomorrow?"*
3. Observe the agent's execution log:
   - **Step 1**: Calls `fetch_calendar_events`.
   - **Observation**: Finds `Coffee with Paul` at `Starbucks, Market St, San Francisco, CA`.
   - **Step 2**: The LLM extracts the city `"San Francisco"` from the address.
   - **Step 3**: Calls `get_weather_forecast` with parameter `{ "cityName": "San Francisco" }`.
   - **Observation**: Receives 68°F and Clear Sky.
   - **Step 4**: Synthesizes the response in chat:
     > *"Your meeting with Paul tomorrow at 2:00 PM is at Starbucks on Market Street in San Francisco. The weather in San Francisco is forecasted to be clear and pleasant, around 68°F (20°C). No rain is expected."*

Notice that you never explicitly told the agent where Paul was meeting you or what city to look up. The agent resolved the location dynamically from the calendar observation.

<Exercise title="Handle Ambiguous Locations">
Suppose an event location is entered as `"The Office"`. 

How can you instruct the agent in the System Prompt to handle unspecific locations?

<SolutionToggle>
Add a fallback rule to the AI Agent System Message:
```text
LOCATION FALLBACK RULE:
If a calendar event specifies a generic location (e.g. "The Office", "Conference Room", "Home") or specifies no location at all, assume the user's home city of "San Francisco" when querying weather forecasts.
```
This prevents the agent from attempting to query weather for the literal string "The Office".
</SolutionToggle>
</Exercise>
