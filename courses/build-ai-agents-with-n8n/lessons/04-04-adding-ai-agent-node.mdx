Now that our chat trigger is in place, we arrive at the core orchestrator of our entire architecture: the **AI Agent** node.

In this lesson, we attach the AI Agent node, wire it to an OpenAI Large Language Model (the Brain), connect Window Buffer Memory (the State), and verify conversational retention across multiple dialogue turns.

```
[ When chat message received ]
               │
               ▼
    [ Planner AI Agent ] (Tools Agent)
      ├── Chat Model (Purple Port: OpenAI GPT-4o-mini, Temp: 0.2)
      └── Memory (Blue Port: Window Buffer Memory, Context Window: 7)
```

## Step 1: Add and Name the AI Agent Node

1. On your canvas, click the **+** icon on the output of the Chat Trigger node.
2. In the search palette, type **AI Agent** and select it.
3. Rename the node to:
   ```
   Planner AI Agent
   ```
4. Double-click the node to open its parameters:
   - **Prompt**: Under **Source for Prompt**, select **Connected Chat Trigger Node**. This instructs the agent to treat the user's latest incoming message (`chatInput`) as its primary instruction.
   - **Agent Type**: Ensure **Tools Agent** is selected. The Tools Agent leverages function-calling fine-tuning to select and execute tools with high precision.

## Step 2: Connect the LLM Brain (OpenAI Chat Model)

Notice the colored sub-node connection ports along the bottom of the `Planner AI Agent` node.

1. Click the **+** icon beneath the **Chat Model** port (the purple port).
2. Search for and select **OpenAI Chat Model**.
3. Rename the model node to `OpenAI Summary Generator`.
4. Configure credentials:
   - Under **Credential to connect with**, select your existing OpenAI credential, or click **Create New Credential**.
   - Paste your secret API key from `platform.openai.com/api-keys`.
5. Configure model parameters:
   - **Model**: Select `gpt-4o-mini` (or `gpt-4o`). `gpt-4o-mini` is exceptionally fast, highly reliable for structured tool calls, and very cost-effective for iterative testing.
   - Click **Add Option** and select **Sampling Temperature**. Set the temperature to **`0.2`**.

<Callout type="info" title="Why Low Temperature for Agents?">
In creative writing or brainstorming, a higher temperature (0.7 to 1.0) introduces lexical variety. In agentic tool calling, you want deterministic precision: the agent must strictly format JSON arguments without creative deviation. Setting `temperature = 0.2` minimizes hallucination and syntax errors.
</Callout>

## Step 3: Connect Window Buffer Memory

An assistant that forgets what you said 30 seconds ago cannot maintain a helpful context. We need to attach short-term memory.

1. Click the **+** icon beneath the **Memory** port (the blue port) of the `Planner AI Agent` node.
2. Select **Window Buffer Memory**.
3. Configure the memory parameters:
   - **Session Key**: Leave as default (`sessionId`), which automatically binds to the unique session ID emitted by the Chat Trigger.
   - **Context Window Length**: Set to **`7`**. This instructs n8n to retain the last 7 conversation turns (7 user prompts and 7 agent responses) in memory.

## Step 4: Testing Conversational Recall

Let's verify that the Brain and Memory are functioning before attaching any external tools:

1. Click the **Chat** widget in the bottom right corner of the canvas.
2. Submit Turn 1:
   > *"My next interview is with Google."*
3. The AI Agent passes the message to OpenAI, which responds appropriately (e.g. *"That is exciting! How can I help you prepare for your upcoming Google interview?"*).
4. Now test conversational memory by submitting Turn 2:
   > *"Who am I interviewing with?"*
5. Inspect the response:
   > *"You are interviewing with Google."*

The agent recalled the entity "Google" from the previous turn without needing it re-stated. Intelligence and state are now operational.

<Exercise title="Evaluate Memory Window Limits">
You set the Context Window Length to 3. The user has an extended 10-turn dialogue with the agent. On Turn 10, the user asks:
*"What was the very first topic we discussed today?"*

What will the agent answer, and why?

<SolutionToggle>
Because the window size is set to 3, the memory buffer only contains Turns 7, 8, and 9. 

Turns 1 through 6 have been evicted from the sliding window to save context tokens. The agent will honestly respond that it does not know or that the context does not contain the original topic. If your workflow requires retaining conversation state across days, you must connect long-term memory backends like Redis or PostgreSQL.
</SolutionToggle>
</Exercise>
