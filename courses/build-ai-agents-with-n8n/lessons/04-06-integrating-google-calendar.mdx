With our AI Agent's brain and memory operational, we now give our agent its first real-world capability: **reading your schedule from Google Calendar**.

In this lesson, we attach the Google Calendar Tool to the agent's Tools port, configure OAuth2 authentication, set dynamic time range filters, and test natural language calendar queries.

```
                  [ Planner AI Agent ]
                    ├── Model: OpenAI Chat Model
                    ├── Memory: Window Buffer Memory
                    └── Tools (Orange Port)
                          │
                          ▼
               [ Google Calendar Tool ]
                 - Name: fetch_calendar_events
                 - Calendar: AI Agent Day Planner Calendar
                 - Time Range: Today to Today + 7 Days
```

## Step 1: Add the Google Calendar Tool Node

1. On your canvas, locate the `Planner AI Agent` node.
2. Click the **+** icon beneath the **Tools** port (the orange port).
3. In the search palette, type **Google Calendar**.
4. Select the **Google Calendar** node (under Tools).
5. Rename the node to:
   ```
   fetch_calendar_events
   ```

## Step 2: Configure Google OAuth2 Credentials

1. In the Google Calendar tool configuration window, locate **Credential to connect with**.
2. Select **Create New Credential** -> **Google Calendar OAuth2 API**.
3. Follow the OAuth2 authorization flow:
   - Sign in with the Google account where you created your `AI Agent Day Planner Calendar` in Lesson 15.
   - Grant permission for n8n to view events on your calendars.
   - Click **Save**. n8n confirms the OAuth2 handshake.

## Step 3: Configure Query Parameters and Intervals

Now configure what events the tool fetches:

- **Tool Description**: Leave set to **Set Automatically**. n8n automatically generates a clear natural language description informing the LLM that this tool retrieves Google Calendar events.
- **Resource**: `Event`
- **Operation**: `Get Many`
- **Calendar**: Select **AI Agent Day Planner Calendar** from the dropdown list.
- **Limit**: Set to **`10`** (fetches up to 10 upcoming events).
- **Time Range Filtering**:
  - In the **After** field, click the expression editor (`fx`) and enter:
    ```
    {{ $today }}
    ```
  - In the **Before** field, enter:
    ```
    {{ $today.plus({ days: 7 }) }}
    ```

<Callout type="info" title="Luxon Date Expressions in n8n">
`$today` evaluates to midnight of the current day. `$today.plus({ days: 7 })` creates a rolling 7-day query window. Downstream, the LLM will filter specifically for today or tomorrow depending on the user's prompt.
</Callout>

Click **Execute step** on the tool node: the mock events created in Lesson 15 (`Job Interview with Anthropic`, `Coffee with Paul`, `Sprint Review`) appear in the output schema!

## Step 4: Testing Calendar Dialogue in the Chat

Click **Back to canvas** and open the chat widget to interact directly with your calendar:

- **Prompt 1**: *"List all calendar events."*
  - The agent invokes `fetch_calendar_events`, formats the returned JSON, and outputs a neat bulleted list of all three meetings.
- **Prompt 2**: *"Do I have any interviews scheduled?"*
  - The agent reads the list, identifies the event with title *"Job Interview with Anthropic"*, and reports the exact time and meeting link.
- **Prompt 3**: *"When and where should I meet Paul?"*
  - The agent correctly identifies the Starbucks meeting on Market Street in San Francisco.

## The Critical Problem: The LLM Temporal Blind Spot

Everything seems to be working, but now ask this critical question in the chat:
> *"What is the current date and time?"*

Observe the agent's answer:
> *"I do not have access to real-time information or the current date and time. My training data only extends up to..."*

Or ask:
> *"List all interviews scheduled for tomorrow."*
The agent may return the wrong events or state that it cannot determine what day "tomorrow" is!

Because Large Language Models are pre-trained static neural networks, **they do not know what day or time it is today**. In the next lesson, we solve this temporal blind spot by dynamically injecting real-time timestamps into the AI Agent's system prompt.

<Exercise title="Diagnose Tool Calling Ambiguity">
Suppose you have two tools attached to the agent:
1. `fetch_calendar_events`: Retrieves upcoming events.
2. `search_user_emails`: Searches Gmail messages.

If the user asks: *"When is my flight to Chicago?"*, the agent occasionally searches Gmail and occasionally checks Calendar. How can you make tool selection deterministic?

<SolutionToggle>
Refine the **Tool Descriptions**:
- For `fetch_calendar_events`, specify: *"Use this tool as the primary source for all scheduled times, dates, flights, meetings, and itinerary events."*
- For `search_user_emails`, specify: *"Use this tool only when looking for receipts, ticket confirmation numbers, or email communications not found in the calendar."*

Explicit tool descriptions guide the model's routing logic.
</SolutionToggle>
</Exercise>
