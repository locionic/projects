In this lesson, we build your first complete, functional automation workflow from scratch. We will create an automated **Support Request Notifier**:

1. A customer or internal team member submits a support ticket via an n8n-hosted web form.
2. An **IF** conditional node inspects the urgency level.
3. If marked **Urgent**, the workflow dispatches a formatted alert to a Discord channel.
4. If not urgent, the request routes to a placeholder **No-Op** node for future ticketing backlog sync.

```
[ On Form Submission ] (Trigger)
           │
           ▼
     [ IF Node ] (Is this urgent?)
      ├── True Path ───> [ Discord Send Message ] (Posts to #support-alerts)
      └── False Path ──> [ No-Op Node ] (Placeholder)
```

## Step 1: Create the Form Trigger Node

1. In your n8n workspace, click **Create Workflow** in the upper right corner.
2. Name the workflow `Support Request Notifier`.
3. Click the **+** icon on the canvas, select **On form submission**, and configure the form parameters:
   - **Form Title**: `Submit a Support Request`
   - **Form Description**: `Please describe your issue and indicate whether immediate escalation is required.`
4. Add two form fields:
   - **Field 1**:
     - Field Name: `describe_the_issue`
     - Field Type: `Text`
     - Required Field: `Enabled`
   - **Field 2**:
     - Field Name: `is_this_urgent`
     - Field Type: `Dropdown List`
     - Required Field: `Enabled`
     - Options: Add two choices: `yes` and `no`
5. Click **Test step**. Notice that n8n displays two URLs: a **Test URL** and a **Production URL**. Open the Test URL in a new browser tab, fill in sample data (`describe_the_issue: "Payment gateway checkout failing"`, `is_this_urgent: "yes"`), and click Submit.
6. The test submission appears in n8n as structured JSON.

## Step 2: The Pin Data Productivity Secret

When testing multi-node workflows, having to submit the web form again on every minor change slows down iteration.

In the top right corner of the Form node's output pane, click the **Pin Data** icon (the pushpin). This pins the current test payload into the workflow canvas. Now, whenever you execute downstream nodes, n8n reuses this pinned payload instantly without requiring new form submissions.

<Callout type="info" title="Pinning Data for Development">
Pinned data only applies within the visual editor during testing. It is automatically ignored during live production runs triggered by real users.
</Callout>

## Step 3: Configure the IF Conditional Node

1. Click the **+** icon next to the Form node, select **Flow**, and choose the **IF** node.
2. Rename the node to `Is this urgent?`.
3. Configure the condition:
   - **Value 1**: Drag the `is_this_urgent` field from the left Input Schema pane into the Value 1 input box. n8n inserts the expression: `{{ $json.is_this_urgent }}`.
   - **Operation**: `String is equal to`.
   - **Value 2**: Type `yes`.
4. Click **Execute step**. If your test submission had `yes`, the data will route down the **True** output port; if `no`, it routes down the **False** output port.
5. From the **False** output port, add a **No-Op** (No Operation) node named `Not Urgent`. This serves as a clean visual placeholder for future integrations (such as logging non-urgent tickets into Google Sheets).

## Step 4: Configure Discord Integration

1. On your Discord server, create a new text channel named `#support-alerts`.
2. Navigate to the [Discord Developer Portal](https://discord.com/developers/applications) and click **New Application** (name it `n8n Support Bot`).
3. Under the **Bot** tab, click **Reset Token**, copy the bot token, and save it securely.
4. Under **OAuth2 -> URL Generator**, select the `bot` scope and grant permissions: `Send Messages` and `Embed Links`. Copy the generated URL into a browser window to invite the bot to your server.
5. Back in n8n, click the **+** icon on the **True** branch of the IF node and search for **Discord**.
6. Select **Send a message**. Create a new credential under **Discord Bot API**, paste your Bot Token, and click Save.
7. Configure the node parameters:
   - **Resource**: `Message`
   - **Operation**: `Send`
   - **Channel ID**: Select `#support-alerts` from the dropdown list.
   - **Message**: Enter the following formatted template:

```markdown
🚨 **URGENT SUPPORT REQUEST ESCALATION**

**Issue Description:**
{{ $json.describe_the_issue }}

**Urgent Flag:** {{ $json.is_this_urgent }}
**Received Timestamp:** {{ $now.format('cccc, LLLL d, yyyy HH:mm') }}
```

## Step 5: Test and Activate

1. Click **Execute step** on the Discord node. Check your Discord server: the formatted alert appears immediately in `#support-alerts`!
2. In the upper right corner of the n8n canvas, toggle the **Active** switch to on.
3. Switch the form trigger URL from the Test URL to the **Production URL**.
4. Submit a live ticket through the production form URL. Open the **Executions** tab in n8n: notice that the latest run does **not** have the lab beaker icon, confirming it ran as a true production execution!

<Callout type="info" title="Repeat from Executions">
If a user reports an error with a live production submission, go to the **Executions** tab, click the failed run, and select **Copy to Editor**. n8n copies the exact production payload directly into your canvas so you can debug the failure with real customer data.
</Callout>

<Exercise title="Extend the Workflow">
Modify the `Not Urgent` branch of the workflow to write all non-urgent tickets into a Google Sheet or Notion database instead of terminating at the No-Op node. Which fields from `$json` will you map?

<SolutionToggle>
You would replace the `No-Op` node with a `Google Sheets -> Append Row` or `Notion -> Create Database Page` node.

You will map:
1. `Ticket Description`: `{{ $json.describe_the_issue }}`
2. `Urgency Status`: `{{ $json.is_this_urgent }}`
3. `Created At`: `{{ $now.toISO() }}`
4. `Status`: Literal string `"Backlog / Pending Review"`
</SolutionToggle>
</Exercise>
