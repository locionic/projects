When building an automated daily assistant that will ultimately run every morning at 7:00 AM, beginning development with a **Schedule Trigger** creates massive friction. You would have to manually adjust the cron minute or click execute and simulate triggers repeatedly.

In this lesson, we add the **On chat message** trigger. This provides an interactive chat interface directly inside the n8n canvas, allowing you to converse with your agent, submit test queries, and inspect reasoning logs in real time.

```
[ When chat message received ] (Chat Trigger)
                 │
                 ▼
     [ Planner AI Agent Node ] (Configured in Lesson 17)
```

## Step 1: Create the Workflow Canvas

1. Open your n8n workspace.
2. Click **Create Workflow** in the top right corner.
3. Rename the workflow from `My workflow` to:
   ```
   AI Agent Automation Dayplanning
   ```
4. A blank canvas appears with an empty starting trigger placeholder.

## Step 2: Add the On Chat Message Node

1. Click the **+** icon on the canvas.
2. In the node search palette, search for **Chat**.
3. Select **When chat message received** (under Triggers).
4. Double-click the node to inspect its settings:
   - Notice that n8n displays an interactive chat widget at the bottom right.
   - When a user types a message and hits enter, the node captures the input and emits it as an n8n item.
5. Rename the node to:
   ```
   Daily 7am Trigger (Dev: Chat Mode)
   ```

## The Chat Item Data Contract

When a user submits a message in the chat widget, what does the output item look like?

Inspect the output schema of the chat trigger:

```json
[
  {
    "json": {
      "chatInput": "Create a summary of my agenda for tomorrow and send it to my email.",
      "sessionId": "session_839201a8f",
      "action": "sendMessage"
    }
  }
]
```

- `chatInput`: The raw text query submitted by the user.
- `sessionId`: A unique session identifier generated per browser tab. This key is used downstream by the **Memory** node to associate messages with the correct conversational history.

<Callout type="info" title="Dual-Mode Strategy">
Keeping the chat trigger during active development lets you test ad-hoc edge case questions (such as "What is the weather like for my afternoon meeting?") in seconds. In Lesson 25, we will wire a Schedule Trigger in parallel without touching any of the downstream agent nodes.
</Callout>

<Exercise title="Compare Trigger Mechanics">
How does the data payload emitted by an **On chat message** trigger differ from an **On a schedule** trigger?

<SolutionToggle>
- **On chat message**: Emits a `chatInput` string containing the user's natural language request and a `sessionId`. Downstream agent nodes use this text as their objective.
- **On a schedule**: Emits a timestamp object (e.g. `{{ $now.toISO() }}`) with no text prompt. When transitioning to a schedule trigger, the prompt must be supplied statically within the AI Agent's system instructions or via an upstream Set node.
</SolutionToggle>
</Exercise>
