# CRDTs for collaborative applications

Building real-time collaborative applications—like Google Docs, Figma, or multiplayer games—requires synchronizing state across multiple clients simultaneously. When users make concurrent edits while offline, resolving conflicts when they reconnect is notoriously difficult. 

Conflict-free Replicated Data Types (CRDTs) offer a mathematically sound solution to this problem.

## What is a CRDT?
A CRDT is a data structure that can be replicated across multiple machines. Clients can update the data independently, concurrently, and without coordination. When these replicas eventually communicate and exchange their updates, they are guaranteed to converge to the exact same state, without requiring a central server to resolve conflicts.

## Operational Transforms vs CRDTs
Historically, Operational Transformation (OT) was the standard for collaborative editing. OT requires a central server to order and transform operations to resolve conflicts. This is complex to implement and hard to scale.

CRDTs eliminate the need for a central conflict-resolution server. They achieve convergence through commutative operations (where the order of applying operations doesn't matter). While early CRDTs struggled with large metadata overhead, modern implementations like Yjs and Automerge are highly optimized, making CRDTs the new standard for local-first, collaborative software development.
