## Bộ công cụ tối ưu hóa

<Callout type="idea" title="Mô hình tư duy">
  Mọi kỹ thuật hiệu suất trong Next.js đều hướng tới một trong hai mục tiêu: *hiển thị các pixel đầu tiên trên màn hình nhanh hơn* hoặc *gửi ít JavaScript hơn đến client*. Hãy ghi nhớ điều đó và "tại sao" sẽ trở nên rõ ràng.
</Callout>

<Stepper>
  <Step title="1. Tối ưu hóa hình ảnh — Thành công số 1 cho LCP">

    <ul className="space-y-2 text-sm">
      <li><strong>Chuyển đổi WebP/AVIF tự động</strong> — tệp nhỏ hơn mà không giảm chất lượng</li>
      <li><strong>Kiểm soát kích thước/chất lượng</strong> — phục vụ hình ảnh 300px trên di động, 1200px trên máy tính để bàn</li>
      <li><strong>Ngăn chặn dịch chuyển bố cục</strong> — yêu cầu chiều rộng/chiều cao để trình duyệt dành không gian phù hợp</li>
    </ul>
    
    ```tsx filename="ImageDemo.tsx"
    import Image from 'next/image';

    export function Hero() {
      return (
        <Image
          src="/hero.jpg"

          height={675}
          priority
          className="rounded-xl"
        />
      );
    }
    ```

    <Alert type="warning" title="Quan trọng: Luôn cung cấp chiều rộng và chiều cao">
      Nếu không có cả hai, Next.js không thể dành không gian bố cục và CLS sẽ bị ảnh hưởng. Sử dụng kích thước nội tại thực của hình ảnh của bạn. Nếu nghi ngờ, hãy kiểm tra tệp hình ảnh trong trình duyệt tệp hệ điều hành của bạn hoặc sử dụng trình chỉnh sửa hình ảnh.
    </Alert>
    
  </Step>

  <Step title="2. Tối ưu hóa phông chữ — Loại bỏ FOIT">
    
    Sử dụng mô-đun `next/font`. Nó tải xuống phông chữ tại thời điểm build và phục vụ chúng cục bộ—không có yêu cầu bên thứ ba, không có dịch chuyển bố cục.

        <SuccessAlert title="Những gì bạn nhận được miễn phí">
          <ul className="text-sm space-y-1">
            <li>Tệp phông chữ tự lưu trữ — không có yêu cầu bên ngoài tới Google</li>
            <li>`font-display: swap` tự động — văn bản hiển thị trong khi phông chữ tải</li>
            <li>Tập hợp con theo `subsets` — bỏ các ký tự không sử dụng (ví dụ: bỏ `cyrillic` nếu không sử dụng)</li>
            <li>Biến CSS để tích hợp Tailwind dễ dàng</li>

  <Step title="3. Nhập động — Chia nhỏ mã nặng">
    
    Không tải các thành phần không hiển thị trên lần hiển thị ban đầu. Sử dụng `next/dynamic` để chia mã ở cấp thành phần:
    
    ```tsx filename="dynamic-chart.tsx"
// Heavy chart library: ~200KB gzipped
import dynamic from 'next/dynamic';

// Load it only when needed (client-side, no SSR)
const RevenueChart = dynamic(
  () => import('@/components/RevenueChart'),
  {
    ssr: false,           // ✅ Skip server rendering for this component
    loading: () => <Skeleton />, // ✅ Show placeholder instantly
  }
);

export function Dashboard() {
  return <RevenueChart />;
}
    ```
    
    <Alert type="info" title="Khi nào nên bỏ qua SSR (`ssr: false`)">
      <ul className="text-sm space-y-1">
        <li>Biểu đồ/đồ thị dựa vào `window` hoặc API trình duyệt</li>
        <li>Thư viện hoạt hình nặng (GSAP, Framer Motion)</li>
        <li>Tiện ích của bên thứ ba (Google Maps, Stripe Elements)</li>
        <li>Chuyển đổi chế độ tối — đợi đã, cái này đủ rẻ để render trên máy chủ</li>
      </ul>
    </Alert>
    
    <Accordion type="multiple">
      <AccordionItem title="Code splitting thực sự làm gì?" defaultOpen>
        Nếu không có import động, các bundler có thể nhóm mọi thứ vào một tệp JS duy nhất. Với import động, thành phần sẽ tải trong một chunk riêng biệt chỉ được tìm nạp khi cần. Đây là **công cụ giảm kích thước bundle lớn nhất** cho các ứng dụng vừa và lớn.
      </AccordionItem>
      <AccordionItem title="Tôi nên chia nhỏ bao nhiêu?">
        Sử dụng bộ phân tích bundle (bước 6) để tìm các thành phần nặng nhất của bạn. Thông thường: trình chỉnh sửa văn bản phong phú, biểu đồ, trình xem 3D, tiện ích xác thực. Đừng chia nhỏ quá mức—import động thêm một vòng mạng. Chia nhỏ các thành phần ngăn chặn việc tải xuống JS ban đầu có ý nghĩa.

  <Step title="4. Server Components — Mặc định không gửi JS">
    
    Trong App Router, tất cả các thành phần đều là Server Components theo mặc định. Đây là đòn bẩy hiệu suất lớn nhất của bạn—bạn nhận được kết quả render *mà không* gửi JS của thành phần đó đến trình duyệt.
    
    ```tsx filename="server-component.tsx"
// This entire file runs on the server
// → Zero JavaScript sent to the browser for this component
async function BlogPost({ slug }: { slug: string }) {
  const post = await db.posts.findUnique({ where: { slug } });

  return (
    <article>
      <h1>{post.title}</h1>
      <MDXContent source={post.content} />
    </article>
  );
}
    ```
    
    <Tabs defaultTab="Decision Tree">
      <Tab label="Cây quyết định" icon={<span>🌳</span>}>
        
        ```text filename="decision-flow.txt"
Need a useState, useEffect, onClick, or window?
    └── Yes → Add "use client" (Client Component)
    └── No  → It's already a Server Component (best default)

Server Component delivers:
  ✅ HTML directly to browser (fast FCP)
  ✅ Data fetching on server (no client fetch waterfalls)
  ✅ Zero JS bundle cost for that component
        ```

## Bộ nhớ đệm và luồng dữ liệu

<Callout type="info" title="Các lớp bộ nhớ đệm của Next.js">
  Next.js có nhiều cơ chế bộ nhớ đệm. Hiểu sự khác biệt giúp ngăn chặn 90% sự nhầm lẫn "tại sao dữ liệu của tôi lại cũ?".
</Callout>

<Accordion type="single">
  <AccordionItem title="Các lớp bộ nhớ đệm trong Next.js (App Router)">
    
    <Timeline variant="default">
      <TimelineItem title="Ghi nhớ yêu cầu" status="completed">
        Khi bạn gọi `await fetch(...)` bên trong một Server Component, Next.js sẽ loại bỏ các yêu cầu giống hệt nhau *trong một lần render*. Một yêu cầu giống hệt thứ hai trong cùng một lần render sẽ trả về kết quả được lưu trong bộ nhớ đệm *mà không cần truy cập mạng lại*.
      </TimelineItem>
      <TimelineItem title="Bộ nhớ đệm dữ liệu" status="completed">
        Next.js mở rộng `fetch` với bộ nhớ đệm dữ liệu tích hợp. Kết quả được duy trì (theo mặc định, vĩnh viễn). Các lần render tiếp theo trên các yêu cầu sẽ đọc từ bộ nhớ đệm.
        ```tsx filename="fetch-options.ts"
// Force revalidation every hour
fetch('https://api.example.com/data', {
  next: { revalidate: 3600 } // seconds
});

// No revalidation = cache until you deploy
fetch('https://api.example.com/data');

// Always fresh (no caching)
fetch('https://api.example.com/data', {
  cache: 'no-store'
});
        ```
      </TimelineItem>
      <TimelineItem title="Bộ nhớ đệm toàn bộ tuyến đường" status="current">
        Các trang tĩnh được render tại thời điểm build và được lưu vào bộ nhớ đệm dưới dạng HTML. Một trang tĩnh được phục vụ ngay lập tức—không có tính toán máy chủ tại thời điểm yêu cầu.
      </TimelineItem>
      <TimelineItem title="Bộ nhớ đệm Router (phía Client)" status="pending">
        Bộ nhớ đệm router phía client lưu trữ các trang đã render trong bộ nhớ (và localStorage để điều hướng tiến/lùi). Điều hướng trở lại cảm thấy tức thì vì trang tải từ bộ nhớ đệm.
      </TimelineItem>
    </Timeline>
    
  </AccordionItem>

  <AccordionItem title="Server Actions — Đơn giản hóa việc xác thực lại">
    
    Server Actions làm mờ ranh giới giữa client và server. Gọi chúng từ Client Components, nhưng chúng thực thi trên server với quyền truy cập cơ sở dữ liệu đầy đủ.
    
    ```tsx filename="server-action.ts"
'use server';
import { revalidatePath } from 'next/cache';
import { db } from '@/lib/db';

export async function createPost(formData: FormData) {
  const title = formData.get('title') as string;
  await db.posts.create({ data: { title } });
  revalidatePath('/posts'); // Invalidate the posts cache
}
    ```
    
    <SuccessAlert title="Tại sao lại là Server Actions?">
      Trước Server Actions, "tạo bài đăng" yêu cầu xây dựng một tuyến API đầy đủ, xử lý xác thực trong một lớp riêng biệt và xác thực lại trên client bằng logic thẻ bộ nhớ đệm phức tạp. Server Actions cho phép bạn viết mã phía máy chủ nội tuyến — không có mã API rườm rà, không có quản lý trạng thái phía client cho chính thao tác đó.
    </SuccessAlert>
    
  </AccordionItem>

  <AccordionItem title="Streaming và Suspense — Render lũy tiến">
    
    Thay vì chờ tất cả dữ liệu tải, hãy truyền từng phần HTML khi chúng sẵn sàng:
    
    ```tsx filename="streaming-page.tsx"
// Slow data component — this is the bottleneck
async function SlowChart() {
  const data = await fetch('/api/slow-data').then(r => r.json());
  return <Results data={data} />;
}

// Skeleton shows immediately, content streams in
export default async function DashboardPage() {
  return (
    <div>
      <header>Dashboard</header>          {/* ✅ Instant */}
      <RecentActivity />                   {/* ✅ Fast */}
      <Suspense fallback={<ChartSkeleton />}>  {/* Shows skeleton */}
        <SlowChart />                      {/* Streams when ready */}
      </Suspense>
    </div>
  );
}
    ```
    
    <InfoAlert title="Cách SSR + Streaming hoạt động cùng nhau">
      Server Components vẫn chạy trên máy chủ. *Sự khác biệt* với Suspense là phản hồi truyền các chunk khi chúng sẵn sàng. Vỏ gửi ngay lập tức, dữ liệu chậm gửi sau. Người dùng thấy nội dung dần dần thay vì chờ một phản hồi HTML lớn.
    </InfoAlert>
    
  </AccordionItem>
</Accordion>

## Phân tích gói nâng cao

<Callout type="warning" title="Biết bạn đang gửi gì">
  Một import không được tối ưu hóa có thể thêm hơn 200KB vào gói client của bạn. Bộ phân tích gói làm cho những thứ vô hình trở nên hữu hình.
</Callout>

<Stepper>
  <Step title="Cài đặt @next/bundle-analyzer">

    ```bash title="Install"
npm install -D @next/bundle-analyzer
    ```
    
  </Step>

  <Step title="Thiết lập next.config.js">
    
    ```javascript filename="next.config.js"
const withBundleAnalyzer = require('@next/bundle-analyzer')({
  enabled: process.env.ANALYZE === 'true',
});
module.exports = withBundleAnalyzer({});
    ```
    
  </Step>

  <Step title="Chạy bộ phân tích">
    
    ```bash title="Terminal"
ANALYZE=true npm run build
    ```
    
    Mở URL mà nó in ra (thường là `http://localhost:3000/_next/analyze/...`). Bạn sẽ thấy một treemap trong đó các hộp lớn hơn = các gói lớn hơn. Di chuột để xem cái gì đang chiếm không gian.
    
  </Step>

## Nhưng chờ đã, còn nhiều hơn thế

<Accordion type="multiple">
  <AccordionItem title="Prefetching & Link">
    
    `<Link>` từ `next/link` tự động tìm nạp trước các trang được liên kết trong khung nhìn (khi người dùng có kết nối nhanh):
    
    ```tsx filename="prefetch-link.tsx"
import Link from 'next/link';

<Link href="/en/blog/nextjs-performance">  {/* ✅ Prefetched when visible */}
  Read more
</Link>

<Link href="/heavy-page" prefetch={false}>  {/* ⬇️ Skip prefetch */}
  Heavy page (saves bandwidth on mobile)
</Link>
    ```
    
  </AccordionItem>

  <AccordionItem title="Tìm nạp song song & tuần tự">
    
    Tìm nạp dữ liệu song song giúp giảm đáng kể các thác nước:
    
    ```tsx filename="parallel-fetch.tsx"
// ❌ Sequential: 200ms + 300ms = 500ms total
async function SlowPage() {
  const user  = await fetch('/api/user').then(r => r.json());   // 200ms
  const posts = await fetch('/api/posts').then(r => r.json()); // 300ms
  return <Dashboard user={user} posts={posts} />;
}

// ✅ Parallel: max(200ms, 300ms) = 300ms total
async function FastPage() {
  const [user, posts] = await Promise.all([
    fetch('/api/user').then(r => r.json()),
    fetch('/api/posts').then(r => r.json()),
  ]);
  return <Dashboard user={user} posts={posts} />;
}
    ```
    
  </AccordionItem>

  <AccordionItem title="Cấu hình phân đoạn tuyến đường">
    
    Kiểm soát hành vi render trên mỗi trang với cấu hình phân đoạn tuyến đường:
    
    ```tsx filename="route-config.tsx"
export const dynamic = 'force-static';  // Always static, even in dev
export const revalidate = 3600;           // Revalidate every hour
export const fetchCache = 'force-no-store'; // Never use data cache

// For one-off routes without creating a separate layout:
export const metadata = {
  title: 'My Page',
  robots: { index: false },  // Prevent indexing this page
};
    ```
    
  </AccordionItem>
</Accordion>
