Next.js 15 giới thiệu Partial Prerendering (PPR), một chiến lược render mới được thiết kế để tối ưu hóa hiệu suất cảm nhận và Thời gian đến Byte đầu tiên (TTFB) cho các trang có cả nội dung tĩnh và động. PPR tận dụng Suspense và Server Components của React để cung cấp một phản hồi streaming lai, kết hợp một shell tĩnh được pre-render với các "lỗ hổng" được stream động. Tài liệu này sẽ phân tích kiến trúc, chi tiết triển khai, cơ chế caching và các cân nhắc vận hành của PPR.

## Tổng quan kiến trúc PPR

PPR thay đổi cơ bản mô hình render phía máy chủ bằng cách tách rời các phần tĩnh và động của một trang. Thay vì chờ tất cả các thao tác lấy dữ liệu hoàn tất trước khi gửi bất kỳ HTML nào, PPR ngay lập tức stream một shell HTML tĩnh. Shell này chứa các placeholder cho nội dung động, sau đó sẽ được stream khi chúng có sẵn. Cách tiếp cận này khác biệt so với SSR truyền thống (chờ tất cả dữ liệu) và SSG (xây dựng trước mọi thứ).

Các thành phần cốt lõi cho phép PPR là:

1.  **React Server Components (RSC):** Nền tảng cho việc render phía máy chủ và lấy dữ liệu.
2.  **React Suspense:** Điều phối việc streaming nội dung động. Các component được bọc trong `<Suspense>` trở thành các "lỗ hổng" tiềm năng trong shell tĩnh.
3.  **Next.js Runtime:** Quản lý quá trình build, render phía máy chủ và streaming HTTP.
4.  **`experimental.ppr` Flag:** Kích hoạt tối ưu hóa PPR trong quá trình phát triển và build sản phẩm.

Khi một yêu cầu đến một trang được bật PPR:

1.  Next.js xác định các phần tĩnh của trang và bất kỳ ranh giới `<Suspense>` nào.
2.  Một shell HTML tĩnh, bao gồm CSS và JavaScript cho các phần tĩnh, được gửi ngay lập tức đến client. Shell này chứa nội dung dự phòng cho các phần động bị tạm dừng.
3.  Đồng thời, máy chủ lấy dữ liệu cho các phần động trong các ranh giới `<Suspense>`.
4.  Khi dữ liệu động có sẵn, các đoạn HTML tương ứng được stream đến client, thay thế nội dung dự phòng.
5.  Quá trình hydration phía client sau đó xảy ra trên HTML đã nhận đầy đủ.

Điều này giúp cải thiện đáng kể TTFB và First Contentful Paint (FCP) vì trình duyệt nhận được HTML có thể render nhanh hơn nhiều.

## Bật PPR

PPR là một tính năng thử nghiệm trong Next.js 15. Để bật nó, hãy cấu hình `next.config.js` của bạn:

```javascript
// next.config.js
/** @type {import('next').NextConfig} */
const nextConfig = {
  experimental: {
    ppr: true, // Enable Partial Prerendering
    // Other experimental flags can go here
  },
  // Other Next.js configurations
};

module.exports = nextConfig;
```

Với `ppr: true`, Next.js sẽ phân tích các component trang của bạn trong quá trình build để xác định các phân đoạn tĩnh và động.

## Ví dụ mã: PPR trong thực tế

Hãy xem xét một trang chi tiết sản phẩm, nơi thông tin sản phẩm tương đối tĩnh, nhưng các đánh giá của người dùng lại rất động và có thể mất nhiều thời gian hơn để lấy.

```tsx
// app/products/[slug]/page.tsx
import { Suspense } from 'react';
import ProductDetails from './ProductDetails';
import ProductReviews from './ProductReviews';
import LoadingReviews from './LoadingReviews'; // Fallback component

interface ProductPageProps {
  params: { slug: string };
}

// Simulate a slow data fetch for product details (static-ish)
async function getProduct(slug: string) {
  const products = {
    'nextjs-book': {
      id: 'nextjs-book',
      name: 'Next.js 15 Deep Dive',
      price: 49.99,
      description: 'An authoritative guide to Next.js 15 features.',
    },
    'react-patterns': {
      id: 'react-patterns',
      name: 'Advanced React Patterns',
      price: 39.99,
      description: 'Mastering modern React development.',
    },
  };
  await new Promise(resolve => setTimeout(resolve, 100)); // Simulate network latency
  return products[slug];
}

export default async function ProductPage({ params }: ProductPageProps) {
  const product = await getProduct(params.slug);

  if (!product) {
    return <div>Product not found.</div>;
  }

  return (
    <div className="container mx-auto p-4">
      <h1 className="text-3xl font-bold mb-4">{product.name}</h1>
      <p className="text-lg text-gray-700 mb-6">${product.price.toFixed(2)}</p>
      <ProductDetails description={product.description} />

      <h2 className="text-2xl font-semibold mt-8 mb-4">Customer Reviews</h2>
      {/* This Suspense boundary defines a dynamic "hole" */}
      <Suspense fallback={<LoadingReviews />}>
        <ProductReviews productId={product.id} />
      </Suspense>
    </div>
  );
}

// app/products/[slug]/ProductDetails.tsx
// This is a Server Component
interface ProductDetailsProps {
  description: string;
}

export default function ProductDetails({ description }: ProductDetailsProps) {
  return (
    <div className="bg-gray-100 p-6 rounded-lg shadow-md">
      <h3 className="text-xl font-medium mb-2">Product Description</h3>
      <p className="text-gray-800">{description}</p>
    </div>
  );
}

// app/products/[slug]/ProductReviews.tsx
// This is a Server Component that fetches dynamic data
interface ProductReviewsProps {
  productId: string;
}

interface Review {
  id: string;
  author: string;
  rating: number;
  comment: string;
}

async function getProductReviews(productId: string): Promise<Review[]> {
  // Simulate a much slower data fetch for reviews
  await new Promise(resolve => setTimeout(resolve, 2000));
  return [
    { id: 'r1', author: 'Alice', rating: 5, comment: 'Excellent book!' },
    { id: 'r2', author: 'Bob', rating: 4, comment: 'Very informative.' },
  ].filter(review => productId === 'nextjs-book'); // Example filtering
}

export default async function ProductReviews({ productId }: ProductReviewsProps) {
  const reviews = await getProductReviews(productId);

  if (reviews.length === 0) {
    return <p>No reviews yet. Be the first!</p>;
  }

  return (
    <div className="space-y-4">
      {reviews.map(review => (
        <div key={review.id} className="border p-4 rounded-md bg-white shadow-sm">
          <div className="flex justify-between items-center mb-2">
            <span className="font-semibold">{review.author}</span>
            <span className="text-yellow-500">{'⭐'.repeat(review.rating)}</span>
          </div>
          <p className="text-gray-700">{review.comment}</p>
        </div>
      ))}
    </div>
  );
}

// app/products/[slug]/LoadingReviews.tsx
// This is a Client Component or Server Component for the fallback UI
export default function LoadingReviews() {
  return (
    <div className="animate-pulse space-y-4">
      <div className="h-24 bg-gray-200 rounded-md"></div>
      <div className="h-24 bg-gray-200 rounded-md"></div>
    </div>
  );
}
```

Trong ví dụ này:

*   Component `ProductPage` lấy thông tin chi tiết sản phẩm cơ bản. Dữ liệu này tương đối nhanh.
*   Component `ProductDetails` render mô tả tĩnh.
*   Component `ProductReviews` lấy các đánh giá, được cố ý làm chậm. Nó được bọc trong `<Suspense>`.
*   `LoadingReviews` cung cấp giao diện dự phòng ngay lập tức.

Khi trang này được yêu cầu, trình duyệt sẽ nhận được HTML cho tên sản phẩm, giá và component `ProductDetails`, cùng với dự phòng `LoadingReviews`. Sau 2 giây, HTML `ProductReviews` sẽ được stream vào và thay thế dự phòng.

## Hồ sơ thời gian tồn tại của Cache

PPR giới thiệu khái niệm "hồ sơ thời gian tồn tại của cache" để quản lý độ tươi mới của shell tĩnh. Điều này rất quan trọng vì mặc dù shell là tĩnh, dữ liệu nó chứa có thể trở nên cũ. Next.js 15 cho phép định nghĩa `cacheLife` cho các thao tác lấy dữ liệu, ảnh hưởng đến thời gian shell tĩnh vẫn còn hợp lệ.

Tùy chọn `cacheLife` thường được sử dụng với các yêu cầu `fetch` trong Server Components. Nó quy định tuổi tối đa của dữ liệu có thể được sử dụng để tạo shell tĩnh.

```tsx
// Example of using cacheLife with fetch
async function getProduct(slug: string) {
  const res = await fetch(`https://api.example.com/products/${slug}`, {
    next: {
      revalidate: 3600, // Revalidate every hour
      cacheLife: '10s', // The static shell generated with this data is valid for 10 seconds
    },
  });
  return res.json();
}
```

**Hiểu về `cacheLife`:**

*   **`cacheLife: '10s'`**: Điều này có nghĩa là nếu dữ liệu được lấy bởi lệnh gọi `fetch` này cũ hơn 10 giây, Next.js sẽ coi shell tĩnh được tạo bằng dữ liệu này là cũ. Một yêu cầu mới sẽ kích hoạt việc render lại shell tĩnh.
*   **`cacheLife: 'forever'`**: Shell tĩnh được tạo bằng dữ liệu này được coi là luôn mới. Điều này phù hợp với nội dung thực sự bất biến.
*   **`cacheLife: '0s'`**: Shell tĩnh được tạo bằng dữ liệu này ngay lập tức được coi là cũ. Điều này có nghĩa là shell sẽ luôn được render lại trên mỗi yêu cầu, làm mất đi một số lợi ích của PPR đối với dữ liệu cụ thể đó.

`cacheLife` hạn chế nhất trong số tất cả các thao tác lấy dữ liệu đóng góp vào shell tĩnh sẽ xác định `cacheLife` tổng thể của shell. Các lỗ hổng động (nội dung trong `<Suspense>`) không ảnh hưởng trực tiếp đến `cacheLife` của shell tĩnh, vì chúng được stream độc lập.

## Các mẫu lấy dữ liệu không được memoize

Trong PPR, việc lấy dữ liệu trong Server Components không yêu cầu memoization rõ ràng (ví dụ: `React.memo` hoặc `useMemo`) để đạt hiệu suất. Kiến trúc của Next.js và React xử lý điều này một cách hiệu quả. Mỗi lệnh gọi `fetch` trong một Server Component sẽ tự động được loại bỏ trùng lặp trong suốt thời gian của một yêu cầu duy nhất.

Tuy nhiên, điều quan trọng là phải hiểu rằng các lệnh gọi `fetch` *bên ngoài* ranh giới `<Suspense>` đóng góp vào shell tĩnh và `cacheLife` của nó. Các lệnh gọi `fetch` *bên trong* ranh giới `<Suspense>` là một phần của lỗ hổng động và được stream sau.

```tsx
// app/page.tsx
import { Suspense } from 'react';
import StaticHeader from './StaticHeader';
import DynamicContent from './DynamicContent';
import LoadingFallback from './LoadingFallback';

async function getGlobalConfig() {
  // This fetch contributes to the static shell.
  // Its cacheLife will influence the shell's validity.
  const res = await fetch('https://api.example.com/config', {
    next: { revalidate: 60, cacheLife: '1h' }
  });
  return res.json();
}

export default async function HomePage() {
  const config = await getGlobalConfig(); // Data for static shell

  return (
    <div>
      <StaticHeader appName={config.appName} />
      <Suspense fallback={<LoadingFallback />}>
        <DynamicContent /> {/* This will stream later */}
      </Suspense>
    </div>
  );
}

// app/DynamicContent.tsx
async function getLatestPosts() {
  // This fetch is inside a Suspense boundary.
  // It will be fetched and streamed independently.
  // Its revalidate setting still applies for its own data freshness.
  const res = await fetch('https://api.example.com/posts/latest', {
    next: { revalidate: 10 }
  });
  return res.json();
}

export default async function DynamicContent() {
  const posts = await getLatestPosts();
  return (
    <section>
      <h2>Latest Posts</h2>
      <ul>
        {posts.map((post: any) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </section>
  );
}
```
