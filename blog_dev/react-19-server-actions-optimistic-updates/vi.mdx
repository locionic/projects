**React 19 giải quyết vấn đề này một cách nguyên bản (natively).** Bằng cách kết hợp **Server Actions** với các hook `useOptimistic` và `useActionState`, React mang lại độ trễ cảm nhận tức thì 0ms, đồng thời đảm bảo tính nhất quán tuyệt đối của trạng thái nếu một tác vụ thay đổi dữ liệu ở backend thất bại.

Trong bài phân tích chuyên sâu này, chúng ta sẽ khám phá cách React 19 điều phối các transition đồng thời, thực thi phía server, và rollback optimistic tức thì mà không cần đến các thư viện quản lý trạng thái của bên thứ ba.

## Kiến trúc Production hoàn chỉnh: Lượt thích & Bình luận

<Tabs defaultValue="action">
  <Tab label="1. Server Action (Server)" value="action">

```tsx title="actions/postActions.ts" showLineNumbers
"use server";

import { revalidatePath } from "next/cache";

export type ActionResponse = {
  success: boolean;
  likesCount?: number;
  error?: string;
};

export async function toggleLikeAction(
  postId: string,
  currentLikes: number
): Promise<ActionResponse> {
  try {
    // Giả lập ghi vào cơ sở dữ liệu
    await new Promise((resolve) => setTimeout(resolve, 800));
    
    // Giả lập lỗi ngẫu nhiên để minh họa khả năng rollback mạnh mẽ
    if (Math.random() < 0.1) {
      throw new Error("Network timeout while updating likes table");
    }

    const updatedLikes = currentLikes + 1;
    revalidatePath(`/blog/${postId}`);
    return { success: true, likesCount: updatedLikes };
  } catch (err: any) {
    return { success: false, error: err.message || "Failed to register like" };
  }
}
```

  </Tab>

  <Tab label="2. Optimistic Component (Client)" value="client">

```tsx title="components/LikeButton.tsx" showLineNumbers
"use client";

import { useOptimistic, useTransition, useState } from "react";
import { toggleLikeAction } from "@/actions/postActions";

interface LikeButtonProps {
  postId: string;
  initialLikes: number;
}

export function LikeButton({ postId, initialLikes }: LikeButtonProps) {
  const [likes, setLikes] = useState(initialLikes);
  const [isPending, startTransition] = useTransition();

  // useOptimistic phản ánh ngay lập tức ý định của người dùng
  const [optimisticLikes, setOptimisticLikes] = useOptimistic(
    likes,
    (current, increment: number) => current + increment
  );

  const handleLike = async () => {
    startTransition(async () => {
      // 1. Tăng UI ngay lập tức ở phía client
      setOptimisticLikes(1);

      // 2. Thực hiện Server Action
      const result = await toggleLikeAction(postId, likes);

      if (result.success && result.likesCount !== undefined) {
        // 3. Xác nhận trạng thái từ server
        setLikes(result.likesCount);
      } else {
        // 4. Rollback xảy ra tự động vì state không được cập nhật!
        alert(`Error: ${result.error || "Could not save like"}`);
      }
    });
  };

  return (
    <button
      onClick={handleLike}
      disabled={isPending}
      className="inline-flex items-center gap-2 px-5 py-2.5 rounded-full bg-red-50 dark:bg-red-950/40 text-red-600 dark:text-red-400 font-semibold hover:scale-105 active:scale-95 transition-all shadow-sm disabled:opacity-75"
    >
      <span>❤️</span>
      <span>{optimisticLikes} Likes</span>
      {isPending && <span className="animate-pulse text-xs text-gray-400">Saving...</span>}
    </button>
  );
}
```

## Checklist 4 bước cho UI Optimistic hoàn hảo

<Stepper>
  <Step title="1. Luôn bọc trong một Transition">
    Các giá trị từ `useOptimistic` chỉ giữ trạng thái tạm thời của chúng trong khi một React transition đang hoạt động. Luôn gọi action của bạn bên trong `startTransition` hoặc truyền trực tiếp vào `<form action={...}>`.
  </Step>
  <Step title="2. Tạo ID tạm thời ổn định">
    Khi thêm các mục vào danh sách một cách optimistic, hãy tạo một UUID tạm thời (`crypto.randomUUID()`) để React có thể `key` các mục trong danh sách một cách chính xác trước khi server tạo ra ID thực sự từ cơ sở dữ liệu.
  </Step>
  <Step title="3. Xử lý cả lỗi Rejection và lỗi từ Server">
    Server Actions nên trả về các đối tượng có cấu trúc như `{ success: false, error: "..." }` thay vì để promise bị reject không được xử lý, để các component phía client có thể hiển thị thông báo thân thiện (toast) trong quá trình rollback.
  </Step>
  <Step title="4. Chỉ Revalidate những gì đã thay đổi">
    Sử dụng `revalidatePath` hoặc `revalidateTag` một cách chi tiết trong Next.js Server Actions để tránh làm mất hiệu lực toàn bộ cache của trang và buộc phải re-render toàn trang tốn kém.
  </Step>
</Stepper>

## Các câu hỏi thường gặp

<FAQ>
  <Question>`useOptimistic` có thay thế các thư viện quản lý trạng thái toàn cục (Zustand, Redux) không?</Question>
  <Answer>
    Không. `useOptimistic` được thiết kế đặc biệt để xử lý các tác vụ thay đổi dữ liệu đang chờ (pending mutations) trong các transition bất đồng bộ. Mặc dù nó thay thế các thư viện fetching phía client cho việc gửi form, các store toàn cục như Zustand vẫn là lựa chọn lý tưởng cho các trạng thái chỉ tồn tại ở client và cần chia sẻ giữa nhiều trang (như chuyển đổi theme sáng/tối hoặc trình phát âm thanh).
  </Answer>

  <Question>Server Actions có thể được gọi bên ngoài các form HTML không?</Question>
  <Answer>
    Có! Bạn có thể gọi Server Actions bên trong các trình xử lý `onClick`, `useEffect`, hoặc các custom hook bằng cách bọc lệnh gọi trong `startTransition(async () => { await myAction(); })`.
  </Answer>

  <Question>React 19 ngăn chặn việc gửi dữ liệu trùng lặp như thế nào?</Question>
  <Answer>
    React 19 cung cấp trạng thái `isPending` thông qua `useActionState` và `useFormStatus`, cho phép bạn vô hiệu hóa các nút gửi hoặc thực hiện debounce cho các input trong khi một server action đang được xử lý.
  </Answer>
</FAQ>
