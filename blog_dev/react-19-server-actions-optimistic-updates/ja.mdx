<Alert type="warning" title="300msのインタラクションの罠">
  ユーザーが「いいね」を押したり、商品をカートに追加したり、コメントを送信したりする際に、ネットワークの往復に200〜500ms待たされると、アプリケーションは動作が遅く、反応が鈍いと感じられます。しかし、自動ロールバック機能なしにローカルの状態を安易に変更すると、リクエスト失敗時に「ゴーストデータ」が生まれてしまいます。

**React 19は、この問題をネイティブに解決します。** **サーバーアクション**と`useOptimistic`、`useActionState`フックを組み合わせることで、Reactは知覚レイテンシー0msの即時フィードバックを提供しつつ、バックエンドのミューテーションが失敗した場合には絶対的な状態整合性を保証します。

この詳細な解説では、React 19がサードパーティの状態管理ライブラリなしに、どのようにして並行トランジション、サーバーサイド実行、そして即時のオプティミスティック・ロールバックを協調させるのかを探ります。

## オプティミスティックUIのライフサイクルとロールバックの流れ

低速な3G接続環境やサーバータイムアウトが発生した際に、ユーザーがフォームを送信すると裏側では何が起こるのでしょうか？

    actor ユーザー
    participant UI as クライアントUI (useOptimistic)

    participant Server as サーバーアクション (DB書き込み)

## 本番環境を想定した完全なアーキテクチャ: いいねとコメント

<Tabs defaultValue="action">
  <Tab label="1. サーバーアクション（サーバー側）" value="action">

```tsx title="actions/postActions.ts" showLineNumbers
"use server";

import { revalidatePath } from "next/cache";

export type ActionResponse = {
  success: boolean;
  likesCount?: number;
  error?: string;
};

export async function toggleLikeAction(
  postId: string,
  currentLikes: number
): Promise<ActionResponse> {
  try {
    // Simulate database write
    await new Promise((resolve) => setTimeout(resolve, 800));
    
    // Random failure simulation for resilient rollback demonstration
    if (Math.random() < 0.1) {
      throw new Error("Network timeout while updating likes table");
    }

    const updatedLikes = currentLikes + 1;
    revalidatePath(`/blog/${postId}`);
    return { success: true, likesCount: updatedLikes };
  } catch (err: any) {
    return { success: false, error: err.message || "Failed to register like" };
  }
}
```

  </Tab>

  <Tab label="2. オプティミスティックコンポーネント（クライアント側）" value="client">

```tsx title="components/LikeButton.tsx" showLineNumbers
"use client";

import { useOptimistic, useTransition, useState } from "react";
import { toggleLikeAction } from "@/actions/postActions";

interface LikeButtonProps {
  postId: string;
  initialLikes: number;
}

export function LikeButton({ postId, initialLikes }: LikeButtonProps) {
  const [likes, setLikes] = useState(initialLikes);
  const [isPending, startTransition] = useTransition();

  // useOptimistic immediately reflects user intention
  const [optimisticLikes, setOptimisticLikes] = useOptimistic(
    likes,
    (current, increment: number) => current + increment
  );

  const handleLike = async () => {
    startTransition(async () => {
      // 1. Instantly increment UI locally
      setOptimisticLikes(1);

      // 2. Perform Server Action
      const result = await toggleLikeAction(postId, likes);

      if (result.success && result.likesCount !== undefined) {
        // 3. Confirm server state
        setLikes(result.likesCount);
      } else {
        // 4. Auto-rollback occurs automatically because state was not modified!
        alert(`Error: ${result.error || "Could not save like"}`);
      }
    });
  };

  return (
    <button
      onClick={handleLike}
      disabled={isPending}
      className="inline-flex items-center gap-2 px-5 py-2.5 rounded-full bg-red-50 dark:bg-red-950/40 text-red-600 dark:text-red-400 font-semibold hover:scale-105 active:scale-95 transition-all shadow-sm disabled:opacity-75"
    >
      <span>❤️</span>
      <span>{optimisticLikes} Likes</span>
      {isPending && <span className="animate-pulse text-xs text-gray-400">Saving...</span>}
    </button>
  );
}
```

## 完璧なオプティミスティックUIを実現するための4ステップチェックリスト

<Stepper>
  <Step title="1. 常にTransitionでラップする">
    `useOptimistic`の値が一時的な状態を保持するのは、Reactのトランジションがアクティブな間だけです。アクションの呼び出しは常に`startTransition`でラップするか、`<form action={...}>`に直接渡してください。
  </Step>
  <Step title="2. 安定した一時IDを生成する">
    リストに項目をオプティミスティックに追加する場合、一時的なUUID (`crypto.randomUUID()`)を生成してください。これにより、サーバーが真のデータベースIDを生成する前に、Reactがリスト項目を正しくキー付けできます。
  </Step>
  <Step title="3. Promiseのrejectとサーバーエラーの両方を処理する">
    サーバーアクションは、未処理のPromiseリジェクトをスローするのではなく、構造化された`{ success: false, error: "..." }`オブジェクトを返すようにしてください。これにより、クライアントコンポーネントはロールバック時に分かりやすいトースト通知を表示できます。
  </Step>
  <Step title="4. 変更があった箇所のみを再検証する">
    Next.jsのサーバーアクションでは、粒度の細かい`revalidatePath`や`revalidateTag`を使用してください。これにより、ページ全体のキャッシュを無効化し、コストの高いフルページ再レンダリングを強制するのを避けることができます。
  </Step>
</Stepper>

## よくある質問（FAQ）

<FAQ>
  <Question>useOptimisticはグローバル状態管理ライブラリ（Zustand, Redux）を置き換えるものですか？</Question>
  <Answer>
    いいえ。`useOptimistic`は非同期トランジション中のペンディング状態のミューテーションを扱うために特化して設計されています。フォーム送信におけるクライアントサイドのフェッチングライブラリを置き換えることはありますが、テーマの切り替えやオーディオプレイヤーのような、ページをまたぐクライアント専用の状態には、Zustandのようなグローバルストアが依然として理想的です。
  </Answer>

  <Question>サーバーアクションはHTMLフォームの外から呼び出せますか？</Question>
  <Answer>
    はい！ `onClick`ハンドラや`useEffect`、カスタムフック内で`startTransition(async () => { await myAction(); })`のように呼び出しをラップすることで、サーバーアクションを起動できます。
  </Answer>

  <Question>React 19はどのようにして二重送信を防ぎますか？</Question>
  <Answer>
    React 19は`useActionState`と`useFormStatus`を通じて`isPending`状態を公開します。これにより、サーバーアクションの実行中に送信ボタンを無効にしたり、入力をデバウンスしたりすることが可能になります。
  </Answer>
</FAQ>
