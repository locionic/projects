This guide details the construction of a local-first, serverless lakehouse architecture leveraging Apache Iceberg, DuckDB, MinIO, and PyIceberg. The objective is to provide a robust, hands-on framework for data engineers and architects to understand and implement advanced data management capabilities such as ACID transactions, schema evolution, partition evolution, and time-travel querying in a lightweight, embedded environment.

### Architectural Overview

The proposed architecture establishes a self-contained data environment suitable for development, testing, or small-scale analytical workloads.

*   **MinIO**: Serves as the S3-compatible object storage layer. All data files (Parquet, ORC, Avro) and Iceberg metadata files (manifests, manifest lists, snapshot files) reside here. Its local deployment provides high availability and performance within the defined scope.
*   **Apache Iceberg**: The open table format that sits atop MinIO. Iceberg manages the table's schema, partitioning, and data files through a sophisticated metadata layer. It enables advanced features like ACID transactions, schema evolution without data rewrite, partition evolution, and time travel.
*   **PyIceberg**: The Pythonic interface for interacting with Iceberg tables. It allows programmatic creation, modification, and inspection of Iceberg tables, including schema and partition management. PyIceberg acts as the bridge between your application logic and the Iceberg metadata stored in MinIO.
