## Những Thay Đổi Thực Sự: WASI Preview 2 và Mô hình Component

Hai yếu tố đã giúp Wasm phía máy chủ trở nên khả thi là WASI và Mô hình Component. Chúng thường được nhắc đến cùng nhau nhưng lại giải quyết các vấn đề khác nhau.

**WASI (WebAssembly System Interface)** cung cấp cho các module Wasm một cách để giao tiếp với máy chủ: đọc tệp, tạo kết nối mạng, lấy biến môi trường. WASI Preview 1 là một không gian tên phẳng kiểu POSIX. WASI Preview 2 (ổn định từ đầu năm 2025) đã tái cấu trúc mọi thứ thành các giao diện khả năng được định kiểu, được định nghĩa bởi **WIT** (WebAssembly Interface Types):

```wit
// http-handler.wit
package my:service;

interface handler {
  use wasi:http/types@0.2.0.{incoming-request, outgoing-response, response-outparam};
  handle: func(request: incoming-request, response-out: response-outparam);
}

world http-service {
  export handler;
}
```

Tệp WIT này là hợp đồng của bạn. Các công cụ tự động tạo ra các ràng buộc cho máy chủ và khách. Module không biết liệu nó đang chạy trong Wasmtime, runtime của Cloudflare, hay Spin — máy chủ sẽ thực hiện giao diện.

**Mô hình Component** đóng gói các module Wasm thô thành các component có thể liên kết với nhau. Hai component được biên dịch từ các ngôn ngữ khác nhau — ví dụ, một thư viện xử lý hình ảnh Rust và một lớp điều phối Python — có thể gọi trực tiếp lẫn nhau thông qua các giao diện WIT mà không cần thông qua JSON hoặc HTTP. Runtime sẽ kết nối chúng lại với nhau.

## Cloudflare Workers: Wasm Thực Tế Trong Sản Xuất

Cloudflare Workers chạy Wasm nguyên bản và có lẽ là runtime Wasm được sử dụng rộng rãi nhất trong môi trường sản xuất hiện nay. Mỗi Worker là một module Wasm được thực thi trong một isolate. Thời gian khởi động lạnh được đo bằng micro giây, không phải giây:

```javascript
// worker.js — loading a compiled Rust Wasm module
import wasm from './my-lib_bg.wasm';
import { init, process_payload } from './my-lib.js';

export default {
  async fetch(request) {
    await init(wasm);
    const body = await request.arrayBuffer();
    const result = process_payload(new Uint8Array(body));
    return new Response(result, {
      headers: { 'content-type': 'application/json' }
    });
  }
};
```

Phần Rust biên dịch thành `wasm32-unknown-unknown` với `wasm-bindgen`:

```rust
use wasm_bindgen::prelude::*;
use serde_json::Value;

#[wasm_bindgen]
pub fn process_payload(data: &[u8]) -> String {
    let parsed: Value = serde_json::from_slice(data)
        .unwrap_or(Value::Null);
    // ... processing logic
    serde_json::to_string(&parsed).unwrap()
}
```

Xây dựng và triển khai:
```bash
wasm-pack build --target bundler
wrangler deploy
```

Module khởi động trong khoảng ~0.3ms đối với các yêu cầu lạnh. Để so sánh, một lần khởi động lạnh của Node.js Lambda thường là 200-800ms.

## Fermyon Spin: Xây dựng Microservices HTTP với Wasm

[Spin](https://developer.fermyon.com/spin) là ví dụ rõ ràng nhất về một framework backend gốc Wasm. Bạn viết các component bằng Rust, Python, Go, hoặc JS — mỗi component xử lý một tuyến đường cụ thể:

```toml
# spin.toml
spin_manifest_version = 2

[application]
name = "api-service"
version = "0.1.0"

[[trigger.http]]
route = "/users/..."
component = "user-handler"

[[trigger.http]]
route = "/auth/..."
component = "auth-handler"

[component.user-handler]
source = "target/wasm32-wasip1/release/user_handler.wasm"
allowed_outbound_hosts = ["https://db.internal"]

[component.auth-handler]
source = "target/wasm32-wasip1/release/auth_handler.wasm"
allowed_outbound_hosts = []
```

Trường `allowed_outbound_hosts` là mô hình khả năng đang hoạt động: `auth-handler` không có quyền truy cập mạng. Ngay cả khi ai đó khai thác một lỗi trong logic phân tích cú pháp JWT của bạn, module cũng không thể gọi về nhà.

Component Rust cho trình xử lý người dùng:

```rust
use spin_sdk::http::{IncomingRequest, ResponseBuilder};
use spin_sdk::http_component;
use spin_sdk::variables;

#[http_component]
async fn handle(req: IncomingRequest) -> anyhow::Result<impl IntoResponse> {
    let db_url = variables::get("db_url")?;
    // Spin's built-in SQLite or PostgreSQL via spin_sdk::pg
    let conn = spin_sdk::pg::Connection::open(&db_url).await?;
    let rows = conn.query("SELECT id, name FROM users LIMIT 20", &[]).await?;

    let users: Vec<serde_json::Value> = rows.iter().map(|r| {
        serde_json::json!({
            "id": r.get::<i64>(0),
            "name": r.get::<&str>(1)
        })
    }).collect();

    Ok(ResponseBuilder::new(200)
        .header("content-type", "application/json")
        .body(serde_json::to_vec(&users)?)
        .build())
}
```

Triển khai lên Fermyon Cloud hoặc tự lưu trữ với `spin up`. Toàn bộ dịch vụ là một tập hợp các tệp `.wasm` và một TOML — không có Dockerfile, không có container registry.

## Nhúng Wasmtime vào một Dịch vụ Python

Nếu bạn có một dịch vụ Python hiện có và muốn chạy các plugin Wasm một cách an toàn — ví dụ, cho phép người dùng tải lên logic biến đổi mà bạn sẽ thực thi — các ràng buộc Python của Wasmtime là công cụ phù hợp:

```python
from wasmtime import Store, Module, Linker, WasiConfig
from pathlib import Path

class WasmPluginRunner:
    def __init__(self, wasm_path: str):
        self.store = Store()
        wasi = WasiConfig()
        wasi.inherit_stdout()
        self.store.set_wasi(wasi)

        self.linker = Linker(self.store.engine)
        self.linker.define_wasi()

        module = Module.from_file(self.store.engine, wasm_path)
        self.instance = self.linker.instantiate(self.store, module)

    def run_transform(self, input_data: bytes) -> bytes:
        memory = self.instance.exports(self.store)["memory"]
        transform = self.instance.exports(self.store)["transform"]

        # Allocate in Wasm linear memory, call the function, read result back
        alloc = self.instance.exports(self.store)["alloc"]
        ptr = alloc(self.store, len(input_data))
        memory.write(self.store, input_data, ptr)

        result_ptr = transform(self.store, ptr, len(input_data))
        # Read length prefix + data from result_ptr
        result_len = int.from_bytes(
            memory.read(self.store, result_ptr, result_ptr + 4), 'little'
        )
        return bytes(memory.read(self.store, result_ptr + 4, result_ptr + 4 + result_len))
```

Tác giả plugin biên dịch mã Rust của họ thành `wasm32-wasip2`, gửi cho bạn tệp `.wasm`. Họ không thể đọc biến môi trường của bạn, không thể mở kết nối mạng, không thể truy cập hệ thống tệp của bạn. Sandbox là mô hình bảo mật.

## Kiểm tra Thực tế Hiệu suất

| Tải công việc | V8 JS | Native | Wasm (Wasmtime) |
|---|---|---|---|
| Mã băm SHA-256 (1MB) | 12ms | 2.1ms | 2.4ms |
| Phân tích cú pháp JSON (10MB) | 89ms | — | 94ms (sử dụng serde) |
| Thay đổi kích thước hình ảnh (Lanczos) | 340ms | 41ms | 48ms |
| Khởi động lạnh (trình xử lý HTTP) | 180ms (Node) | — | 0.3ms |

Wasm chậm hơn khoảng 5-20% so với native đối với các tác vụ nặng tính toán do chi phí gọi gián tiếp và kiểm tra giới hạn. Đối với hầu hết các tải công việc máy chủ bị giới hạn I/O, sự khác biệt này không quan trọng. Lợi thế khởi động lạnh là yếu tố khác biệt thực sự trong các triển khai biên/serverless.

## Wasm Vẫn Kém Ở Điểm Nào

Đừng sử dụng Wasm cho:

- **Kết nối dài hạn** — WebSockets, SSE. Hầu hết các runtime Wasm được thiết kế dựa trên các mẫu yêu cầu-phản hồi.
- **Đa luồng nặng** — Mô hình đa luồng (`wasm-threads`) được hỗ trợ trong trình duyệt nhưng có sự hỗ trợ không đồng đều trong các runtime máy chủ.
- **Tải công việc nặng về bộ nhớ** — Giới hạn bộ nhớ tuyến tính 4GB không phải là vấn đề thực tế hiện nay, nhưng không gian địa chỉ đơn có nghĩa là không có các thủ thuật bộ nhớ ảo.
- **Lặp lại nhanh chóng** — Thời gian biên dịch từ Rust sang Wasm là đáng kể. Đối với các script thay đổi hàng giờ, Python hoặc JS vẫn thắng về tốc độ lặp lại.

## Khung Quyết định Thực tế

Sử dụng Wasm trong môi trường sản xuất khi bạn cần ít nhất hai trong số các yếu tố sau:
1. **Khởi động lạnh dưới mili giây** (biên/serverless)
2. **Cách ly plugin** (mã người dùng không đáng tin cậy, đa người thuê)
3. **Kết hợp đa ngôn ngữ** (lõi quan trọng về hiệu suất bằng Rust + keo Python)
4. **Hiệu suất dự đoán được** (không có tạm dừng GC trong đường dẫn nóng)

Sử dụng container khi bạn cần kết nối dài hạn, công cụ quan sát trưởng thành, hoặc quy trình làm việc Docker hiện có của nhóm bạn.
