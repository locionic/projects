When you deploy a fresh Ubuntu server, it comes with reasonable defaults but significant security gaps. This isn't a theoretical discussion—it's a pragmatic, step-by-step checklist to harden your environment before you expose it to the internet. 

![Featured Ubuntu Security](/static/images/featured_ubuntu_security.jpg)

## Initial Setup and SSH Hardening

The first step is securing your front door. Default SSH configurations are notoriously vulnerable to brute-force attacks and automated scanning scripts.

![SSH Hardening](/static/images/ssh_hardening.jpg)

First, create a new non-root user with sudo privileges and disable root login. Then, restrict SSH access exclusively to key-based authentication.

```bash
# Disable root login and password authentication
sudo nano /etc/ssh/sshd_config

# Ensure these lines are set:
PermitRootLogin no
PasswordAuthentication no
```

Restart the SSH service to apply changes:

```bash
sudo systemctl restart ssh
```

## Firewall Configuration with UFW

An unconfigured firewall leaves all ports open. Ubuntu's Uncomplicated Firewall (UFW) provides a straightforward interface for managing iptables.

![UFW Firewall](/static/images/ufw_firewall.jpg)

Set default policies to deny incoming traffic and allow outgoing traffic. Then, explicitly allow the ports you need.

```bash
# Set default policies
sudo ufw default deny incoming
sudo ufw default allow outgoing

# Allow SSH, HTTP, and HTTPS
sudo ufw allow ssh
sudo ufw allow http
sudo ufw allow https

# Enable the firewall
sudo ufw enable
```

Check the status to verify your rules:

```bash
sudo ufw status verbose
```

## Intrusion Prevention with Fail2Ban

Even with key-based authentication, continuous SSH connection attempts waste server resources and pollute logs. Fail2Ban monitors logs for malicious activity and automatically bans offending IP addresses.

![Fail2Ban Defense](/static/images/fail2ban_defense.jpg)

Install the package and create a local configuration override:

```bash
sudo apt update
sudo apt install fail2ban -y

# Create local config
sudo cp /etc/fail2ban/jail.conf /etc/fail2ban/jail.local
```

Enable and start the service:

```bash
sudo systemctl enable fail2ban
sudo systemctl start fail2ban
```

## Automated Security Updates

Manual patching is a failing strategy. Unattended-upgrades ensures your server automatically pulls and installs critical security patches.

![Automated Updates](/static/images/auto_updates.jpg)

Install and configure the package:

```bash
sudo apt install unattended-upgrades -y
sudo dpkg-reconfigure --priority=low unattended-upgrades
```

This ensures your server stays protected against zero-day vulnerabilities without manual intervention.

<FAQ>
  <Question>How do I disable root login over SSH in Ubuntu?</Question>
  <Answer>
    Open `/etc/ssh/sshd_config`, locate `PermitRootLogin`, change its value to `PermitRootLogin no`, set `PasswordAuthentication no`, save the file, and run `sudo systemctl restart ssh` (or `ssh.service`).
  </Answer>

  <Question>What are the best default UFW firewall rules for a web server?</Question>
  <Answer>
    Run `sudo ufw default deny incoming`, `sudo ufw default allow outgoing`, `sudo ufw allow OpenSSH` (or custom SSH port), and `sudo ufw allow 'Nginx Full'` (ports 80 and 443), then enable with `sudo ufw enable`.
  </Answer>

  <Question>How does Fail2ban protect against brute force SSH attacks?</Question>
  <Answer>
    Fail2ban continuously monitors log files (such as `/var/log/auth.log`) for repeated failed login attempts. When an IP exceeds the configured retry threshold within a given time window, Fail2ban dynamically injects iptables firewall rules to drop incoming packets from that IP.
  </Answer>
</FAQ>
