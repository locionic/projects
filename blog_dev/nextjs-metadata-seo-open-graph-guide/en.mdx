## Why Social Cards Are Your Highest-Converting Traffic Engine

When developers or readers share your article link on X (Twitter), LinkedIn, Discord, or Slack, how does it appear?

Does it generate a rich, high-resolution preview card with an eye-catching visual, engaging headline, and concise summary? Or does it display a barren, broken link with a generic domain fallback?

Research from Buffer and HubSpot indicates that links accompanied by rich **Open Graph summary cards receive over 3.2x higher click-through rates (CTR)** compared to plain text URLs.

In the Next.js App Router, the old patterns of injecting `<Head>` components from `next/head` are officially obsolete. In their place is a unified, strongly typed **Metadata API** that seamlessly handles static definitions, asynchronous `generateMetadata()` data-fetching, canonical URL resolution, and dynamic edge-generated social graphics.

## Refactoring Legacy `<Head>` to Next.js App Router Metadata

Here is how legacy Next.js Pages Router metadata transforms into modern, type-safe App Router metadata:

<CodeMorph
  language="typescript"
  beforeCode={`// ❌ Old Pages Router: Imperative <Head> injection in page component
import Head from 'next/head';

export default function BlogPost({ post }) {
  return (
    <>
      <Head>
        <title>{post.title} | My Blog</title>
        <meta name="description" content={post.summary} />
        <meta property="og:title" content={post.title} />
        <meta property="og:description" content={post.summary} />
        <meta property="og:image" content={post.coverImage} />
        <meta name="twitter:card" content="summary_large_image" />
      </Head>
      <article>
        <h1>{post.title}</h1>
      </article>
    </>
  );
}`}
  afterCode={`// ✅ Modern App Router: Declarative, strictly typed generateMetadata()
import type { Metadata, ResolvingMetadata } from 'next';

interface Props {
  params: { slug: string };
}

export async function generateMetadata(
  { params }: Props,
  parent: ResolvingMetadata
): Promise<Metadata> {
  const post = await getPostBySlug(params.slug);
  if (!post) return {};

  const previousImages = (await parent).openGraph?.images || [];

  return {
    title: post.title,
    description: post.summary,
    alternates: {
      canonical: \`https://locionic.com/en/blog/\${post.slug}\`,
    },
    openGraph: {
      title: post.title,
      description: post.summary,
      url: \`https://locionic.com/en/blog/\${post.slug}\`,
      siteName: 'Locionic Developer Blog',
      images: [
        {
          url: post.coverImage,
          width: 1200,
          height: 630,
          alt: post.title,
        },
        ...previousImages,
      ],
      type: 'article',
      publishedTime: post.date,
    },
    twitter: {
      card: 'summary_large_image',
      title: post.title,
      description: post.summary,
      images: [post.coverImage],
      creator: '@locionic',
    },
  };
}`}

## The 4 Golden Rules of Social Card Optimization

### 1. The 1200 x 630 Standard
Both Twitter and Facebook specify an aspect ratio of roughly **1.91:1**. Creating your Open Graph images at **1200px width by 630px height** ensures crisp rendering on high-DPI displays without awkward automatic cropping.

### 2. Title and Description Length Limits
- **Title:** Keep under **60 characters**. Anything longer gets truncated with an ellipsis on mobile SERPs and Twitter cards.
- **Description:** Keep between **140 and 160 characters**. This gives search engines and social platforms enough context without being chopped off.

### 3. Absolute Image URLs Are Mandatory
Social crawlers (like `facebookexternalhit` or `Twitterbot`) do not execute JavaScript and cannot resolve relative paths like `/static/images/og.png`. Always prefix your image URLs with your full domain name: `https://locionic.com/static/images/og.png`.

### 4. Canonical URLs Prevent Duplicate SEO Penalties
If your content is accessible under multiple URLs (e.g. `/?utm_source=twitter` or `/en/blog/post`), setting `alternates: { canonical: '...' }` instructs Google to concentrate all ranking authority on the primary canonical URL.
