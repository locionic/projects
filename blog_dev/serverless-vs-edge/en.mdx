# Serverless vs Edge computing

Serverless computing allows developers to build and run applications without thinking about servers. The cloud provider automatically provisions, scales, and manages the infrastructure required to run the code. Functions are executed on demand, and you only pay for the compute time you consume.

Edge computing, on the other hand, moves compute power physically closer to the end-user or the data source. Instead of sending data to a centralized data center (like `us-east-1`), computation happens at the "edge" of the network—on CDN nodes, IoT gateways, or local edge servers.

## The Convergence
Increasingly, these two paradigms are converging. "Edge Serverless" (like Cloudflare Workers or AWS Lambda@Edge) allows developers to deploy stateless functions that run globally at the network edge, combining the zero-maintenance benefits of serverless with the ultra-low latency of edge computing. 

Choosing between traditional serverless and edge computing often comes down to data gravity and latency requirements. If a function needs to query a massive, centralized database, running it at the edge might actually increase latency due to database round trips. If it only needs to manipulate HTTP headers or serve static content, edge is the clear winner.
