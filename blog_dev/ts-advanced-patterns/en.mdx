# Advanced TypeScript Patterns for Enterprise Applications

TypeScript has become the undisputed king of large-scale web development. However, many developers merely scratch the surface, using it as "JavaScript with interfaces." To truly unlock TypeScript's potential in an enterprise environment, you need to leverage its advanced type system. 

This post delves into sophisticated TypeScript patterns that prevent runtime errors, improve developer experience, and make your codebase self-documenting.

## 1. Branded Types (Opaque Types)

In enterprise applications, you often have multiple IDs—User IDs, Product IDs, Order IDs—that are all fundamentally strings or numbers. Passing a `ProductID` to a function expecting a `UserID` is a common source of bugs that standard TypeScript cannot catch.

**Branded Types** solve this by attaching a nominal "brand" to a primitive type.

```typescript
// Define the branding utility
type Brand<K, T> = K & { __brand: T };

// Create branded types
type UserId = Brand<string, 'UserId'>;
type ProductId = Brand<string, 'ProductId'>;

// Factory functions to create them
const makeUserId = (id: string) => id as UserId;
const makeProductId = (id: string) => id as ProductId;

// Usage
function fetchUser(id: UserId) { /* ... */ }

const productId = makeProductId('prod_123');
const userId = makeUserId('user_456');

// fetchUser(productId); // ERROR! Type 'ProductId' is not assignable to type 'UserId'.
fetchUser(userId); // Works perfectly
```

By using Branded Types, you enforce semantic meaning at compile time, eliminating an entire class of domain-logic errors.

## 2. Conditional Types for API Responses

When building wrappers around complex APIs, the shape of the response often depends on the input parameters. Conditional types allow you to express these relationships dynamically.

Imagine an API where if you request detailed information, you get a full object; otherwise, you just get an ID.

```typescript
interface UserBasic {
  id: string;
}

interface UserDetailed extends UserBasic {
  name: string;
  email: string;
  role: string;
}

// Conditional type
type UserResponse<TDetailed extends boolean> = 
  TDetailed extends true ? UserDetailed : UserBasic;

// Function signature
declare function fetchUser<T extends boolean>(
  id: string, 
  detailed: T
): Promise<UserResponse<T>>;

async function app() {
  // TypeScript knows 'basic' is UserBasic
  const basic = await fetchUser('123', false); 
  
  // TypeScript knows 'detailed' is UserDetailed
  const detailed = await fetchUser('123', true);
  console.log(detailed.email); 
}
```

This pattern is heavily used in modern libraries like Prisma and tRPC to provide exact typings based on query shapes.

## 3. Template Literal Types for Routing

Introduced a few versions ago but fully matured now, Template Literal Types allow you to parse string patterns at compile time. This is incredibly powerful for typed routing.

```typescript
type Route = 
  | '/users' 
  | `/users/${string}` 
  | '/products' 
  | `/products/${string}`;

function navigate(route: Route) {
  console.log(`Navigating to ${route}`);
}

navigate('/users'); // OK
navigate('/users/123'); // OK
// navigate('/settings'); // ERROR: Argument of type '"/settings"' is not assignable...
```

You can even extract parameters from the route string:

```typescript
type ExtractRouteParams<T extends string> = 
  T extends `${string}/:${infer Param}/${infer Rest}`
    ? { [K in Param | keyof ExtractRouteParams<`/${Rest}`>]: string }
    : T extends `${string}/:${infer Param}`
      ? { [K in Param]: string }
      : {};

// Result: { id: string; tab: string }
type Params = ExtractRouteParams<'/users/:id/:tab'>;
```

This enables frameworks to provide completely type-safe routing where passing the wrong parameter name or type results in a compile-time error.

## 4. The "Builder" Pattern with Method Chaining

For constructing complex objects (like configuration setups or SQL queries), the Builder pattern is ideal. We can use TypeScript's `this` polymorphic type to ensure type safety during method chaining.

```typescript
class QueryBuilder<T = {}> {
  private query: any = {};

  select<K extends string>(fields: K[]): QueryBuilder<T & Record<K, any>> {
    this.query.select = fields;
    return this as any;
  }

  where(condition: any): this {
    this.query.where = condition;
    return this;
  }

  execute(): Promise<T[]> {
    return Promise.resolve([this.query]); // Mock execution
  }
}

async function run() {
  const qb = new QueryBuilder();
  
  const result = await qb
    .select(['id', 'name'])
    .where({ active: true })
    .execute();

  // TypeScript knows result is { id: any, name: any }[]
  console.log(result[0].name);
}
```

## Conclusion

TypeScript is a phenomenally powerful language if you invest the time to understand its deeper mechanics. By adopting branded types, conditional types, template literals, and advanced structural patterns, you can drastically reduce your reliance on runtime checks and unit tests. The compiler becomes your strongest ally, enforcing business logic and preventing regression in complex enterprise applications.
