# Vector databases and RAG (Retrieval-Augmented Generation)

Large Language Models (LLMs) are incredibly powerful, but they suffer from hallucinations and have a knowledge cutoff date. To build reliable, enterprise-grade AI applications, developers are turning to Retrieval-Augmented Generation (RAG).

## What is RAG?
RAG is an architecture that grounds an LLM's responses in factual, proprietary data. Before sending a user's prompt to the LLM, the system retrieves relevant information from a knowledge base and injects it into the prompt's context window. This allows the LLM to synthesize an answer based on specific, up-to-date data it wasn't explicitly trained on.

## The Role of Vector Databases
Traditional relational databases search for exact keyword matches. Vector databases, however, search by semantic similarity. They store data as high-dimensional mathematical vectors (embeddings). When a user asks a question, the query is converted into a vector, and the database performs a nearest-neighbor search to find the most conceptually similar documents.

Systems like Pinecone, Milvus, and pgvector (for PostgreSQL) are essential infrastructure for RAG applications. They enable lightning-fast similarity searches across millions of documents, providing the real-time context that LLMs need to generate accurate, hallucination-free responses.
