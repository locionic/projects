As React applications scale, the folder structure transitions from being a matter of aesthetic preference to a critical architectural decision. With the introduction of the Next.js App Router, the paradigm shifted significantly. We moved away from the legacy `pages/` directory—which often served as a catch-all for both routing and UI components—towards an opinionated, convention-based routing system inside the `app/` directory.

However, the App Router's flexibility, specifically its support for colocation, can easily lead to a chaotic codebase if not managed with a strict architectural philosophy. In this comprehensive guide, we will explore how to architect a highly scalable folder structure for Next.js App Router applications, drawing inspiration from Feature-Sliced Design (FSD) and production enterprise codebases.

## The App Router Paradigm Shift

The Next.js App Router introduced Server Components by default, streaming, and nested layouts. The most significant structural change is **colocation**. In the `app/` directory, only special convention files (`page.tsx`, `layout.tsx`, `route.ts`, `loading.tsx`, `error.tsx`, `not-found.tsx`) are publicly accessible via HTTP.

This means you can place components, tests, and styles directly alongside your routes:

```text
app/
└── dashboard/
    ├── page.tsx
    ├── layout.tsx
    ├── DashboardGraph.tsx
    ├── dashboard.module.css
    └── dashboard.test.tsx
```

While this works for trivial applications, it breaks down quickly in enterprise environments. As the dashboard grows, the `app/dashboard` folder becomes a dumping ground for hundreds of files, violating the Single Responsibility Principle and making code navigation difficult.

## Route Groups vs Private Folders

Next.js provides two essential folder naming conventions to keep the `app/` directory structured:

### 1. Route Groups `(folder)`
Wrapping folder names in parentheses lets you organize your routes without affecting the public URL path:

```text
app/
├── (marketing)/
│   ├── layout.tsx       # Marketing layout (Header with CTA)
│   ├── page.tsx         # / (Home)
│   └── pricing/
│       └── page.tsx     # /pricing
└── (dashboard)/
    ├── layout.tsx       # App layout (Sidebar navigation)
    ├── settings/
    │   └── page.tsx     # /settings
    └── analytics/
        └── page.tsx     # /analytics
```

### 2. Private Folders `_folder`
Prefixing a folder with an underscore tells Next.js to opt that directory and all its subfolders out of routing:

```text
app/
├── (dashboard)/
│   └── analytics/
│       ├── _components/   # Internal only, /analytics/_components is NOT a route
│       │   ├── Chart.tsx
│       │   └── MetricCard.tsx
│       ├── _lib/
│       │   └── calculations.ts
│       └── page.tsx
```

## Recommended Architecture: Feature-Sliced Design

For large applications, we recommend separating routing from domain logic:

```text
src/
├── app/          # 1. Routing and entry points (Next.js native)
├── features/     # 2. Business value and user scenarios (auth, checkout, billing)
├── entities/     # 3. Domain models (user, product, workspace)
└── shared/       # 4. Reusable UI kit, API clients, utilities
```

### 1. The `app/` Layer: Pure Routing & Composition

The `app/` directory should contain minimal business logic. Its primary responsibilities are:
- Defining the route hierarchy.
- Fetching initial data for Server Components.
- Composing features and entities into pages.
- Handling global layouts, error boundaries, and loading states.

```tsx
// app/(dashboard)/analytics/page.tsx
import { AnalyticsChart } from '@/features/analytics-dashboard';
import { getCurrentUser } from '@/entities/user';

export default async function AnalyticsPage() {
  const user = await getCurrentUser();

  return (
    <main className="p-8">
      <h1 className="text-2xl font-bold">Analytics for {user.name}</h1>
      <AnalyticsChart userId={user.id} />
    </main>
  );
}
```

### 2. The `features/` Layer: User Scenarios

A feature delivers specific business value (e.g. `auth-form`, `checkout-modal`, `team-invite`). Features are self-contained:

```text
features/auth-form/
├── ui/                 # React components (LoginForm.tsx, SignupForm.tsx)
├── model/              # State management & hooks (useAuth.ts)
├── api/                # Server Actions and mutation handlers
└── index.ts            # Public API exports
```

Colocate your Server Actions directly in the `api/` segment:

```tsx
// features/auth-form/api/actions.ts
'use server'

import { signIn } from '@/shared/lib/auth';

export async function submitLogin(formData: FormData) {
  const email = formData.get('email') as string;
  const password = formData.get('password') as string;
  return await signIn({ email, password });
}
```

## Strict Import Boundaries

Enforce cross-import rules using ESLint to prevent spaghetti dependencies:

1. **Hierarchy Rule:** A layer can only import from layers below it: `app` -> `features` -> `entities` -> `shared`.
2. **Public API Rule:** Always import through a slice's `index.ts` rather than deep internal files.
3. **Colocation Rule:** If a helper or sub-component is used in only one place, keep it in a `_components` private folder adjacent to its parent.

<FAQ>
  <Question>What is the difference between (folder) and _folder in Next.js App Router?</Question>
  <Answer>
    `(folder)` is a Route Group that groups routes without adding segments to the URL path. `_folder` is a Private Folder that completely opts out of the routing system, preventing any child files from becoming public endpoints.
  </Answer>

  <Question>Where should I put shared components in Next.js App Router?</Question>
  <Answer>
    Place generic, domain-agnostic UI components (like buttons, modals, inputs) in `src/shared/ui/` or `src/components/ui/`. Domain-specific components should live in `src/features/[feature-name]/ui/` or private `_components` folders.
  </Answer>

  <Question>Can I place Server Actions inside component folders?</Question>
  <Answer>
    Yes, you can colocate `'use server'` action files inside feature `api/` segments or private route folders, making mutations easy to locate and maintain alongside the forms that trigger them.
  </Answer>

  <Question>How do double underscore __ folders work in Next.js?</Question>
  <Answer>
    Folders starting with double underscores like `__tests__` or `__mocks__` are treated as private folders by default in Next.js and are never exposed as public HTTP routes.
  </Answer>
</FAQ>
